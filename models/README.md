# models/ — models grouped by training method

All `.keras` models and their scalers are here, **split into four categories by “how they were trained”**.
Picking the wrong category leads to misleading conclusions, so please read [Which one should I use?](#-which-one-should-i-use) first.

Path constants are all defined in [`paths.py`](../paths.py) in the repo root; use the constants in code rather than literal paths.

---

## 🧭 Which one should I use?

| My purpose | Use this | Why |
|---|---|---|
| **Deployment / demo for these 10 known people** | `personalized/from_loso/` | Most accurate after personalization (main muscle r≈0.83) |
| **Deployment / demo for a brand-new person** | any fold of `loso_zeroshot/` | The only models that have not seen the new person |
| **Reporting “cross-subject generalization” in a paper** | `loso_zeroshot/` | ★ **The only honest baseline** |
| **Reporting “the gain from personalization” in a paper** | `loso_zeroshot/` → `personalized/from_loso/` | The starting point must exclude that subject |
| I want the model that has seen the most data | `global/` | ⚠️ Evaluation is inflated, see below |
| Reproducing old numbers from before the coordinate-axis fix | `ablation/before_axisfix/` | |

> 🚫 **Do not use `global/` or `personalized/from_global/` to report generalization scores.**
> They saw (almost) every subject during training; evaluating them is like using past exam papers as the exam.
> Measured, this alone is worth **+0.081** (main muscle r, p=0.0009).

## 📁 The four categories

### 1. `global/` — global training

A single model trained on all subjects' data together. **Convenient for deployment, but cannot be used to evaluate generalization.**

| File | Description |
|---|---|
| `global_fitness_model.keras` | Global model (last epoch) |
| `global_fitness_model_best.keras` | Checkpoint with the best val_loss |
| `global_scaler_ts.pkl` | Time-series feature scaler (**required for inference**) |
| `global_scaler_static.pkl` | Static feature scaler (**required for inference**) |
| `global_feature_spec.pkl` | Feature column definition `{ts_cols, static_cols, feature_mode}` |

* Produced by: [`pipeline/Global_Training_FIXED.py`](../pipeline/Global_Training_FIXED.py)
* For a loading example see the [root README](../README.md#using-the-trained-models-directly)

---

### 2. `loso_zeroshot/` — each LOSO fold (★ honest baseline)

10 folds; each fold **completely excludes** one subject during training and is then evaluated on that subject.
This is the source of every generalization number in this project, and the starting point for personalized fine-tuning.

| File | Description |
|---|---|
| `loso_without_S01.keras` … `loso_without_S10.keras` | Models trained without that subject (10 of them) |
| `loso_scaler_ts_S01.pkl` … `_S10.pkl` | Time-series scaler of each fold (**fit on the training folds only**) |
| `loso_scaler_static_S01.pkl` … `_S10.pkl` | Static scaler of each fold |
| `feature_spec.pkl` | Feature column definition (shared by all 10 folds) |

* Produced by: [`experiments/loso_train_and_save.py`](../experiments/loso_train_and_save.py)
* Results: `results/loso_zeroshot_metrics.csv` (not included in this repo; regenerated by the program above)

**Per-subject zero-shot scores** (performance of `loso_without_{S}.keras` on S):

| Subject | Main muscle r | Synergist r | Main muscle nRMSE |
|---|---|---|---|
| S01 | 0.701 | 0.266 | 0.809 |
| S02 | 0.628 | 0.469 | 0.946 |
| S03 | 0.731 | 0.663 | 0.714 |
| S04 | 0.811 | 0.217 | 0.838 |
| S05 | 0.747 | 0.593 | 0.671 |
| S06 | 0.718 | 0.471 | 1.069 |
| S07 | 0.768 | 0.510 | 0.713 |
| S08 | 0.842 | 0.842 | 0.631 |
| S09 | 0.602 | *0.038* | 0.936 |
| S10 | 0.718 | 0.093 | 0.824 |

> ⚠️ **Do not cite S09's synergist (0.038)** — that channel likely had poor electrode contact
> (coefficient of variation 0.31 vs 0.65–0.92 for everyone else). S09's **main muscle quality is normal** and is fully retained.
> ⚠️ The table above is from a **single run**. There is a ±0.02 drift across runs; in a paper cite the multi-seed
> 0.735 ± 0.013, see the [results table in the root README](../README.md#-main-results).

### 3. `personalized/` — personalized fine-tuning

Fine-tuning an existing model with the subject's own data (feature layers frozen, LR 1e-5, EarlyStopping).

| Subdirectory | Starting model | Honest? | Produced by |
|---|---|---|---|
| **`from_loso/`** | `loso_zeroshot/loso_without_{S}.keras` | ✅ **Leak-free; use this in the paper** | [`experiments/phase2_finetune_loso.py`](../experiments/phase2_finetune_loso.py) |
| `from_loso_nontwo/` | Same as above, but fine-tuned only on non-`_two` data | ✅ Closest to real deployment | [`experiments/finetune_predict_two.py`](../experiments/finetune_predict_two.py) |
| `from_global/` | `global/global_fitness_model.keras` | ⚠️ The starting point has already seen this person | [`pipeline/phase2_finetune_FIXED.py`](../pipeline/phase2_finetune_FIXED.py) |

**These three directories contain no scalers** — fine-tuning does not refit them; reuse the set from the starting model:
`from_loso/S01_personalized.keras` goes with `loso_zeroshot/loso_scaler_{ts,static}_S01.pkl`.

* Results: `results/finetune_results.csv` (before/after comparison; not included in this repo, regenerated by `phase2_finetune_loso.py`)
* `from_loso_nontwo/` has only S02/S04/S06/S08 — only these four have later-recorded `_two` sets

> 🔴 **`from_loso/` is a low draw.**
> This batch's main-muscle r after fine-tuning = 0.814, the lowest of 9 observations (−2.56 sd; the distribution is 0.830 ± 0.006).
> Analyses that load them directly (waveform plots, calibration curves, `finetune_predict_two.py`) are **conservative by about 0.016**.
> This does not change the direction of any conclusion, but **before making figures or demos, rerun `experiments/loso_train_and_save.py` first**
> to obtain base models closer to the centre of the distribution, then fine-tune.

### 4. `ablation/` — ablations and control groups

Use only when a specific comparison needs to be reproduced; **do not cite them as main results**.

| Subdirectory | What it is | Produced by |
|---|---|---|
| `before_axisfix/` | LOSO + personalized models from **before the coordinate-axis fix**. After the fix main muscle r went 0.694→0.726 (p=0.017) | old version of `loso_train_and_save.py` |
| `masked_synergist/` | S09 synergist **masked during training** (handling option ②) | [`experiments/loso_masked_synergist.py`](../experiments/loso_masked_synergist.py) |
| `exclude_s09/` | 9-person LOSO **excluding S09 entirely** (handling option ③) | [`experiments/loso_exclude_s09.py`](../experiments/loso_exclude_s09.py) |
| `holdout_two/` | Global model with the later-recorded `_two` sets as the validation set | [`experiments/train_holdout_two.py`](../experiments/train_holdout_two.py) |

> 📌 The three ways of handling S09 (① exclude from evaluation only / ② mask during training / ③ exclude entirely) **all differ by ≤0.016**,
> showing that the exclusion decision does not affect the conclusions. The official results use ①.

Files in `before_axisfix/`, `masked_synergist/` and `exclude_s09/` are named the same way as in `loso_zeroshot/`
(`loso_without_{S}.keras` + scalers + `feature_spec.pkl`), and each also contains that group's personalized models.

### `legacy_v1/` — early version

Models from early in the project (3–4 subjects, old architecture). **Not compatible with the current pipeline**;
both the input dimensions and the feature definitions differ. Kept only for reference; do not use them for any evaluation.

## 🔧 Loading notes

1. **The model, scaler and feature_spec must come as a set**; never mix different sources.
   `tools/smoke_test.py` catches dimension mismatches right away.
2. Input format: `{'ts_input': (N, 40, 16), 'static_input': (N, 4)}`, output `(N, 2)`.
3. The two output values are **ratios from 0 to 1.5**: normalized to the maximum activation observed for that subject,
   **not a true %MVC** (this project has no MVC recordings); see item 6 of the [root README](../README.md#-read-before-citing-numbers) for details.
4. The window is 40 frames (about 0.67 s @ 60FPS), with the **last frame of the window** as the prediction target; windows **must not cross segment boundaries**.

Verify that all models load correctly:

```bash
python tools/smoke_test.py
```
